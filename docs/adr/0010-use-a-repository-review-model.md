# Use a repository review model

Each Problem has a canonical, versioned repository governed like a protected open-source repository. This is a collaboration model, not a literal Git repository: Supabase stores immutable versions, diffs, relationships, and timeline events. Public Research Threads coordinate questions and approaches like issues, while the Committee marks priority Research Directions. The Primary Steward has sole administrative authority over direction and Committee membership; Committee Members have equal review authority; Site Moderators hold exceptional platform-level override authority. The founder is the sole initial Site Moderator, accepts expressions of Moderator Interest, and appoints additional Site Moderators; appointments and removals are public and timestamped. A Site Moderator may hold other public roles but must recuse from moderation involving their own appointment, Problem, Committee role, or Contribution; if no other Moderator exists, the action waits. An affected account receives one appeal to a different Site Moderator; quarantined material stays preserved and unavailable until that review can occur. More elaborate community governance is deferred until scale demonstrates a need. Scientific protections bind everyone, including the Steward. Human and Agent Contributions are proposed like pull requests; review Agents may assist, but either promotion to Progress or scientific closure requires two conflict-free Committee Member approvals. One reviewer may request changes but cannot dismiss work unilaterally. A Research Brief revision may be proposed by any Committee Member but requires approval from a different Committee Member, and the Steward cannot bypass that protection. Membership changes are public and timestamped without requiring an explanation; removal ends future authority but never erases prior reviews. Closed submissions remain public with a reason, and automated quarantine is limited to objective abuse with human appeal.
